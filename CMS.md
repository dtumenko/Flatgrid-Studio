# Flatgrid Studio — CMS

Projekti se od sada ne pišu ručno u HTML. Svaki projekat je jedan fajl u
`content/work/`, a `scripts/build.mjs` iz njega generiše stranicu projekta i
upisuje ga u `work.html`. Uređuje se kroz panel na `/admin`.

---

## Najkraće moguće

```bash
npm install     # jednom
npm run dev     # svaki put
```

Zatim otvori **http://localhost:5178/admin/**. Dodaj ili izmeni projekat,
klikni **Sačuvaj** — fajlovi se upišu, sajt se odmah ponovo izgradi.
Pogledaj rezultat na http://localhost:5178/work.html.

Kad si zadovoljan:

```bash
git add -A
git commit -m "novi projekat"
git push
```

To je ceo tok. Sve ispod je objašnjenje zašto i šta ako nešto zapne.

---

## Šta je generisano, a šta se piše ručno

| Fajl | Ko ga pravi |
|---|---|
| `work.html` | **build** — ne diraj ga rukom |
| `project-<slug>.html` | **build** — ne diraj ga rukom |
| `sitemap.xml` | **build** |
| `content/work/*.md` | panel (ili ti, u editoru) |
| `templates/work.html`, `templates/project.html` | ti — ovo je *izgled* stranice |
| `index.html`, `studio.html`, `director.html`, `contact.html` | ti — build ih nikad ne dira; panel im menja samo obeležena mesta |
| `academy.html`, `templates.html` | ti — build ih nikad ne dira |
| `content/pages.json` | ti — spisak polja koja panel sme da menja |
| `css/`, `js/` | ti |

Prva dva reda su važna: **svaka ručna izmena u `work.html` ili
`project-*.html` nestaje pri sledećem build-u.** Ako treba da se promeni kako
stranica projekta izgleda — raspored, klase, meta tagovi — to ide u
`templates/project.html`, i onda važi za sve projekte odjednom.

Da nešto ne bi slučajno bilo pregaženo, generisane stranice na kraju nose
komentar `<!-- generated by scripts/build.mjs -->`. Build briše samo
`project-*.html` fajlove koji taj komentar imaju — ručno napisana stranica
je bezbedna i kad joj nestane projekat.

## Dve kolekcije

Panel ima dve stvari u levoj koloni:

- **Projekti** — `content/work/*.md`, iz njih build pravi stranice.
- **Stranice** — Home, Studio, Director i Contact. One nisu generisane;
  panel im menja tekst i slike **na licu mesta, u samom HTML-u**.

Druga kolekcija radi na jednostavnom principu: mesto koje se sme menjati nosi
u HTML-u atribut `data-cms`, na primer

```html
<p class="mag__text" data-cms="studio.read1_text">Design is a discipline…</p>
```

`content/pages.json` kaže samo **koja polja postoje** i kako se zovu u panelu.
Vrednost se nigde ne duplira — uvek se čita iz same stranice. Zato stranicu
možeš i dalje da editovaš rukom: panel će sledeći put pokazati to što si upisao.

Ono što ostaje na tebi: ako prepravljaš stranicu, **ne briši `data-cms`
atribute**. Provera:

```bash
npm run check-pages
```

Ispisuje svako polje iz `pages.json` kome je nestalo sidro, i svako sidro u
stranici koje nije izloženo u panelu.

### Novo polje

Dva koraka. Prvo u HTML:

```html
<h2 class="steps__head up" data-cms="studio.steps_head">Our approach</h2>
```

Pa u `content/pages.json`, u odgovarajuću grupu:

```json
{ "id": "studio.steps_head", "label": "Naslov sekcije", "kind": "text" }
```

`kind` može biti:

| `kind` | šta radi |
|---|---|
| `text` | običan tekst; `&`, `<` i `>` se escape-uju pri upisu |
| `html` | zadržava inline markup — `<em>`, `<br>`, `<sup>` |
| `image` | menja `src` atribut elementa |
| `bg` | menja `url(…)` u `--hero` promenljivoj u `style` atributu |

`bg` postoji zbog hero fotografije na naslovnoj, koja je CSS background a ne
`<img>`. Putanja tu **mora** da ide od korena sajta (`/assets/…`), jer se
`var(--hero)` koristi unutar `css/style.css` pa bi relativna putanja bila
razrešena u odnosu na `/css/`. Panel to sam ispravlja.

Lokalno dev server sme da piše samo u one stranice koje su nabrojane u
`WRITABLE_FILES` u `scripts/dev-server.mjs` — ako dodaješ petu stranicu,
dopiši je i tamo.

## Panel

### Lista

Kolone su naslov, status, slug, opis i godina. Klik na naslov otvara projekat.

- **Status** — `Live` ide na sajt, `Draft` se ne generiše i ne prikazuje se
  na Work stranici. Menja se i direktno iz liste, klikom na pilulu.
- **Redosled** — broj. Manji broj je viši na Work stranici. Isti taj redosled
  određuje šta je „Next project“ u podnožju svake stranice projekta; posle
  poslednjeg se vraća na prvi.
- **⋯ na kraju reda** — otvori, otvori stranicu, obriši.

### Editor

**Osnovno** — naslov, slug, status, redosled, godina.

Slug je deo URL-a: `vellor` → `project-vellor.html`. Kod novog projekta se
sam prati sa naslovom dok ga ne diraš. Kod postojećeg ga menjaj samo ako
zaista hoćeš da promeniš URL — stara stranica se briše i svaki link ka njoj
prestaje da radi.

**Tekst**

- *Podnaslov* — linija ispod imena projekta.
- *Opis za Work listu* — pasus uz projekat na `work.html`.
- *Uvodni pasus* — duži uvod na samoj stranici projekta. Ako je prazan,
  koristi se opis za Work listu.
- *SEO opis* — ono što Google prikazuje. Do ~155 karaktera. Ako je prazan,
  opet se koristi opis za Work listu.

**Specifikacija** — discipline, timeline, klijent. Discipline se koriste na
dva mesta: kao lista na Work stranici i kao `Branding / Art direction / …` u
redu Discipline.

**Naslovna fotografija** — jedna slika koja služi kao veliki kadar na Work
stranici i kao cover na stranici projekta. Format **2000 × 1179**. Verzija za
telefon je manja kopija iste slike koja se koristi kao pozadina na uskim
ekranima; nije obavezna, ali štedi saobraćaj.

**Ploče i poglavlja** — telo stranice projekta, redom kojim je ovde poređano.
Tri vrste bloka:

- **Slika / video** — ploča sa fajlom. Sve ploče su **2000 × 1250**. Prima
  jpg, png, gif ili mp4.
- **Prazan slot** — okvir koji piše šta čeka. Za kad je stranica postavljena
  a fajlovi još nisu stigli.
- **Tekst** — poglavlje: naslov sekcije (npr. *The problem*), jedna rečenica
  kao naslov, pa pasusi. **Prazan red pravi novi pasus.** Ako ostaviš naslov
  praznim, poglavlje se ispiše kao jedan veći pasus bez naslova.

Strelice gore/dole pomeraju blok, × ga uklanja.

## Dva režima

Panel sam prepozna gde radi.

### Lokalno (`localhost`)

Ono što ćeš koristiti 95% vremena. Nema logina. `npm run dev` pokreće server
koji servira sajt i daje panelu dva endpointa — jedan da pročita
`content/work/*.md`, drugi da ih upiše i odmah pokrene build.

Server sluša samo na `127.0.0.1` i piše isključivo u `content/work/` i
`assets/uploads/`. Sve van toga odbija, namerno — greška u panelu ne može da
pregazi ostatak projekta.

Izmene ostaju na tvom disku dok ne uradiš `git push`.

### Preko GitHub-a (na živom sajtu)

Panel na `https://<domen>/admin` traži prijavu GitHub nalogom koji ima pristup
repozitorijumu. Svaka objava je jedan commit — slike i `.md` idu zajedno, pa
hosting pravi jedan build umesto jednog po fajlu.

Ovo radi tek kad se podesi troje:

1. **GitHub OAuth App** (Settings → Developer settings → OAuth Apps).
   Homepage: adresa sajta. Authorization callback URL: `https://<domen>/api/callback`.
2. Na hostingu (Vercel) dodaj promenljive **`OAUTH_CLIENT_ID`** i
   **`OAUTH_CLIENT_SECRET`** iz te aplikacije.
3. `repo` i `siteUrl` u `admin/index.html` moraju da pokazuju na pravi
   repozitorijum i domen.

Bez toga login ne prolazi, ali **lokalni režim radi i dalje** — nezavisan je.

Bitno: u ovom režimu panel upisuje samo `.md`. Stranice nastaju tek kad se
pokrene `npm run build`. Na Vercelu se to dešava samo po sebi (`buildCommand`
u `vercel.json`). Ako sajt stoji na hostingu koji ne pokreće build — običan
FTP, GitHub Pages bez akcije — onda GitHub režim panela nema smisla; radi
lokalno i push-uj gotove stranice.

Režim se može naterati rukom: `/admin?mode=local` ili `/admin?mode=github`.

#### Na Netlify-u

**Prevlačenje zipa neće raditi za panel.** Takav deploy nema ni build ni vezu
sa repozitorijumom — sajt se prikaže, ali `/admin` nema kome da piše i nema
ko da regeneriše stranice. Za samo pokazati sajt kolegi je sasvim dovoljno;
za CMS mora ovako:

1. **Add new site → Import an existing project**, poveži GitHub repozitorijum.
   `netlify.toml` je već u projektu, pa se build komanda i publish folder
   sami pokupe.
2. Napravi GitHub OAuth App (Settings → Developer settings → OAuth Apps).
   Authorization callback URL mora biti tačno
   **`https://api.netlify.com/auth/done`** — Netlify je posrednik, ne tvoj sajt.
3. U Netlify-u: **Site configuration → Access control → OAuth → Install
   provider → GitHub**, pa nalepi Client ID i Client Secret.
4. U `admin/index.html` otkomentariši red `oauthUrl` i upiši ime svog sajta
   u `site_id`.

Tada `/admin` na živom sajtu traži GitHub prijavu, objava je commit, a
Netlify posle commita sam pokrene build.

Fajlovi `api/auth.js` i `api/callback.js` su za Vercel i na Netlify-u se ne
koriste — mogu da ostanu, ništa ne smetaju.

## Slike

Sve što se upload-uje kroz panel ide u `assets/uploads/` sa vremenskim
prefiksom u imenu, tako da nova slika nikad ne pregazi staru.

Postojeće fotografije (`assets/work-vellor.jpg` i ostale) ostaju gde su —
panel ih čita normalno, samo ih ne dira.

Panel ne kompresuje slike. Ubaci ih već pripremljene: ploče **2000 × 1250**,
cover **2000 × 1179**, ispod ~400 KB po komadu.

## Kad nešto zapne

**Panel kaže „Dev server nije pokrenut“** — otvorio si `admin/index.html`
dvoklikom na fajl. Mora preko `npm run dev` i adrese
`http://localhost:5178/admin/`.

**Sačuvao sam, ali stranica izgleda staro** — osveži uz `Ctrl+Shift+R`.
Dev server šalje `no-store`, ali Lenis i fontovi se svejedno keširaju.

**Build puca** — poruka je u terminalu gde je `npm run dev`. Skoro uvek je
neispravan YAML u nekom `content/work/*.md` (najčešće dvotačka u tekstu koji
nije pod navodnicima). Panel to ne može da napravi; ručna izmena fajla može.

**Projekat se ne pojavljuje na Work stranici** — status je `Draft`.

**Polje u kolekciji Stranice je sivo i piše „nema sidra“** — neko je iz HTML-a
obrisao `data-cms` atribut. Pokreni `npm run check-pages` da vidiš koje,
pa ga vrati na element koji je pre nosio.

**Sačuvao sam stranicu, a slika se ne vidi** — proveri da li putanja ide od
korena (`/assets/…`) ako je polje tipa `bg`.

**Stara stranica projekta i dalje postoji** — promenio si slug ručno u `.md`
umesto kroz panel, pa stari fajl nema svoj projekat. Pokreni `npm run build`,
sam će je obrisati.

## Struktura

```
admin/            panel — index.html, cms.js, cms.css
content/work/     jedan .md po projektu ← ovde je sadržaj projekata
content/pages.json  spisak polja koja panel sme da menja na ručnim stranicama
templates/        work.html, project.html ← ovde je izgled
scripts/
  build.mjs       .md → project-*.html + work.html + sitemap.xml
  check-pages.mjs provera da su sidra i content/pages.json u skladu
  dev-server.mjs  lokalni server + API za panel
api/              GitHub OAuth (samo za režim na živom sajtu)
assets/uploads/   sve što je upload-ovano kroz panel
```
